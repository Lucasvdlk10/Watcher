# ADR-001 — UI stdlib Canvas nativo x PySide6/QML

**Estado:** Aceita nesta release de engenharia. **Data:** 21/10/2026. **Autoridade:** compatibilidade e integridade de upgrade de baixo risco.

## Contexto

O briefing prefere PySide6 + QtQuick/QML, por composição translucente, motion, efeitos e escala. Porém o pacote base não inclui Qt e o ambiente de construção não dispõe dos wheels PySide6 Windows offline nem conectividade para obtê-los. Distribuir um instalador "offline" dependente de `pip install PySide6` em tempo de execução não atenderia à especificação. Migrar o core também aumentaria risco desnecessário.

## Escolha

Adotar **Tk 8.6 padrão do Python, com shell desenhado via Canvas e frames personalizados**, imagem original em PNG embarcada e nenhuma árvore de Notebook/Treeview clássico. Conservar os contratos existentes do core e adicionar APENAS consultas opcionais IPC (`ui_snapshot`, `ui_list`). Isso é um redesign real e independente dos widgets legados, e não uma simples recoloração de `ttk`.

## Consequências positivas

- Installer wheel pequeno, offline e por usuário; sem biblioteca Qt ou WebEngine.
- Preserva binários, Python isolado, SQLite, tokens, IPC e regras atuais.
- Empacotamento reproduzível com `setuptools` local; teste sob Xvfb possível.
- Movimento customizado leve, governado por foco e preferências, sem threads gráficas.

## Limitações aceitas

- Não há blur de fundo real nem translucidez/compositor de GPU; os cards aproximam o material por cores e superfícies estratificadas.
- O controle de oclusão total é aproximado via ativação/foco; detecção de oclusão DWM não foi implementada.
- Comportamento exato de acessibilidade Narrator, alto DPI e múltiplos monitores precisa de Windows real.
- Alguns controles secundários (menu de opções e seleção nativa de diretório) continuam usando componentes padrão por melhor compatibilidade.
- A arquitetura não demonstra todos os requisitos de qualidade de uma UI QML comercial; a migração para Qt Quick permanece alternativa futura caso haja kit de wheels legal e testável.

## Alternativas consideradas

1. **PySide6 Qt Quick:** preferida para próximos saltos visuais, mas sem deps offline e sem validação Windows nesta execução.
2. **Electron:** consumo de memória/distribuição maior, superficie WebView e bundle muito grande; rejeitado.
3. **Tkinter/ttk clássico recolorido:** não resolve a aparência antiga; rejeitado.
4. **Canvas nativo customizado:** escolhido para esta entrega; investimento adicional em botões, cards, wave, estados e editor visual.

## Guardrails

Nenhum comando administrativo novo via HTTP; nenhuma dependência remota; nenhum token em UI/logs; dados persistentes e backups intocados fora de operação administrativa explícita. Reavaliar stack somente com pacote offline reproduzível e benchmarking Windows.
